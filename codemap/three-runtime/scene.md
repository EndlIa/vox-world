# src/three-runtime/scene.ts

Ring: 2 · Layer: three-runtime · Depends on: `../document/project.js`, `../voxels/uniform/grid.js`, `three`

## Responsibility
Mirrors the project into a `THREE.Scene`: exactly one `Object3D` per document object plus the output camera, and the derived `InstancedMesh` geometry that renders uniform cells. Owns every derived render resource and the instance-to-cell reverse map. It owns no project data, no renderer, no DOM, and never the viewport camera. It also parents the app's imported raw meshes under their objects' nodes on layer 2 (README D24) — the raw half of the raw-versus-voxel comparison — places each one by its own baked node matrix (README D25), and never owns them: a source mesh, its geometry, and its material belong to the app and are never disposed by the mirror.

## Public interface
```ts
type CellLookup = { objectId: ObjectId; cells: [number, number, number][]; colors: HexColor[] };
class SceneMirror {
  constructor(project: Project, opts?: { background?: HexColor; ambientIntensity?: number });
  readonly scene: THREE.Scene;
  readonly camera: THREE.PerspectiveCamera;            // output camera, scene child named 'camera'
  sync(): void;                                        // rebuilds only objects marked dirty
  markDirty(id: ObjectId): void;
  objectOf(id: ObjectId): THREE.Object3D | undefined;
  contentCenterOf(id: ObjectId): THREE.Vector3;        // local-space center of the object's own content
  previewTransform(id: ObjectId, matrixWorld: THREE.Matrix4): void;  // live gizmo drag: scene only, no document write
  lookupOf(id: ObjectId): CellLookup | undefined;      // instanceId -> cell reverse map
  setSelected(id: ObjectId | null): void;              // draws that object's outline and hides every other's
  renderSelectionOutline(renderer, camera): boolean;   // draws it over the frame, cut by that object alone (D50)
  setMaskMode(enabled: boolean): void;                 // flat per-object maskColor materials
  attachSourceObject(id: ObjectId, source: THREE.Object3D, nodeWorldMatrix: THREE.Matrix4): void;  // raw mesh on layer 2, placed by its baked node matrix
  setSourceVisible(enabled: boolean): void;            // global raw-mesh override, applied at once
  get sourceVisible(): boolean;
  frameAll(camera: THREE.PerspectiveCamera): void;      // fits the given camera to layers 0 and 2
  dispose(): void;
}
```
`ObjectId`/`Project` come from `document/project.js`, `HexColor` from `voxels/uniform/grid.js`; none is re-declared here.

## Internal logic
1. Construction: `scene.background = new THREE.Color(background ?? project.settings.background)`, one `AmbientLight` at `ambientIntensity ?? project.settings.ambientIntensity`, one unconfigurable `DirectionalLight` so cube faces are distinguishable, the one `MeshLambertMaterial` every voxel instance shares — patched with the per-voxel face border (`three-runtime/faceGrid.md`, README D35) — and `camera = new THREE.PerspectiveCamera(project.camera.fov, 1, project.camera.near, project.camera.far)` with `camera.name = 'camera'` and its transform copied from `project.camera.transform`, added as a child of the scene root. That camera is the **output** camera: export and the `camera.fov` track use it and nothing else (README D17, D22). It is not the app's viewport camera; navigation moves the viewport camera, except while the camera lock is on, when the app retargets navigation to this camera (README D17). The mirror itself never moves either camera — it neither creates nor drives the viewport camera, and it never overwrites this one after construction, so the mixer and the composition root keep ownership.
2. `sync()` step 1 — reconcile membership: every `project.objects` entry without a node gets one (`Group` for `representation: 'empty'`; a single `InstancedMesh` for `uniform`), and every mirrored id that left the project has its node removed, its geometry/material/instance buffers disposed, and its lookup dropped.
3. `sync()` step 2 — hierarchy and transform: each node is added under its `parentId`'s node (or the scene root), `node.position/quaternion/scale` are copied from `object.transform`, and `node.visible = object.visible`. The hierarchy comes from `parentId`; nothing is ever read back out of an `Object3D`. The output camera node is created here from `project.camera` (name, transform, fov, near, far) and afterwards belongs to the mixer and the composition root, so `sync()` never overwrites it and cannot fight the timeline.
4. Naming (README D22): every mirrored object node gets `node.name = <ObjectId>` so one `AnimationMixer` rooted at `scene` can bind `obj-4.position`; the camera node is named `camera` for `camera.fov`. Each of those nodes also gets `userData.objectId = id`, the key `picking.ts` resolves a hit back to its object through. Renaming an object never touches `Object3D.name`; the display name lives only in the document.
5. `sync()` step 3 — rebuild dirty objects only (README D4): the ids marked by `markDirty`, plus objects created in step 1. No scheduler, no incremental update graph; a clean object keeps its node, mesh, instance buffers, and lookup identity.
6. Uniform rebuild: one `InstancedMesh` over a `BoxGeometry(cell, cell, cell)` with `cell = grid.cellSize` — one cube the size of this object's own cell, so the geometry is built per rebuild rather than shared across objects at different levels (README D43) — and `count = grid.size`; cell `(x, y, z)` spans one cell from its min corner, so instance `i` gets `setMatrixAt(i, translation of the cell center)` — `(x + 0.5) * cell`, `(y + 0.5) * cell`, `(z + 0.5) * cell`, because the cell coordinate is in cells and the offset it is drawn at is in world units — and `setColorAt(i, color)` in `grid.forEach` order, while `CellLookup.cells[i]` / `.colors[i]` are filled from the same `UniformGrid` in that same order. The mesh records `userData.instanceBase = 0` — the base `picking.ts` adds to a hit's `instanceId` before indexing that lookup. The same rebuild also builds that object's **selection outline** with `@pmndrs/vanilla`'s `Outlines`: the library's inverted hull over the same geometry, instanced through the mesh's **own** `instanceMatrix` — the library assigns that very attribute, so no per-instance copy exists and every cube of the object is wrapped — parented to the mesh, with `screenspace: false` and `thickness = cell * OUTLINE_SHARE` (the mirror owns no renderer, so a pixel-width line is not available to it, and a share of the cell keeps the line proportional at every subdivision), `polygonOffset` so the hull does not fight the faces it wraps, and `SELECTION_COLOR = 0xffd400`. The group is put on `OUTLINE_LAYER = 3`, its own layer rather than the layer-1 decorations, so the pass that draws it can be restricted to it (README D24, D50), and a second copy of the object's instances — sharing that very `instanceMatrix` and drawn with the mirror's one `colorWrite: false` material — goes next to it as the depth the hull is cut against: the same instances, with no other object's depth in the pass to notch the rim. The hull and the copy are both built hidden: `setSelected` is the only thing that shows them. A transform-only object has no outline and no depth copy at all, because it has no instances to wrap.
7. The lookup is built from document data inside the rebuild that creates the instances, and is never derived from mesh, material, or instance-color state. A material swap, `setMaskMode(true)`, or the instance-color stash therefore cannot change what picking reports. A lookup is replaced together with the instances it describes, never patched in place, so a stale `instanceId` cannot resolve to a wrong cell.
8. `setMaskMode(true)` swaps every voxel mesh to a fresh unlit `MeshBasicMaterial({ color: maskColor, toneMapped: false })` and clears `instanceColor` (stashing the attribute) so one render pass produces flat identity frames; `setMaskMode(false)` restores the shared shading material and the stashed colors. Repeated enables are idempotent and never overwrite the stash.
9. `frameAll(camera)` computes the union `Box3` of the mirrored nodes, measuring camera layers 0 and 2 and skipping layer 1 so viewport decorations never widen the frame, then fits the **given** camera to that box: position along the camera's current view direction at `radius / sin(fov/2) * 1.1` from the center, `lookAt` the center, `near`/`far` widened to contain the box, `updateProjectionMatrix()` called. `Box3.setFromObject(node, true)` already includes the node's source-mesh children, so an import frames the imported model before any payload exists; the output camera is never framed here, because it is a document node the user or the timeline owns.
10. `attachSourceObject(id, source, nodeWorldMatrix)` tags `source.userData.objectId = id`, puts it on layer 2 with `source.layers.set(2)` (so the viewport camera draws it, the raycaster can reach it, and the output camera — which tests layer 0 alone — cannot), and records it in the mirror's `sources` map under `id` as one **per-mesh** entry holding the mesh plus a clone of `nodeWorldMatrix`, the baked world matrix of the node that mesh came from (README D25). The clone is deliberate: the caller's matrix belongs to the imported scene and stays live there. The matrix is per mesh because one object holds every mesh of one import (README D28) and those nodes sit at different places: a single matrix shared by the object's meshes would stack them all on the last attached node's pose, which is the overlap this rule exists to prevent. The same mesh attached twice stays one entry (`Array.findIndex` by identity), so a repeated attach cannot duplicate a child, and a second attach of a mesh refreshes the matrix that mesh is placed by. When the node already exists the meshes are parented at once; an id whose node does not exist yet — an import that attaches before the next `sync()` — is attached by the rebuild that creates it.
11. `sync()` step 4 walks every recorded id and applies the same rules the rest of `sync()` applies to derived nodes: parent each mesh under the object's current node when it is not already there (which is how a rebuilt node adopts the meshes of the node it replaced, without a second copy), place it, and set `source.visible = sourceVisible || object.representation === 'empty'`. The rule lives in `applySources`, the only place that writes a source mesh's parent, matrix, `matrixAutoUpdate`, `matrixWorldNeedsUpdate`, or `visible`; `sync()` runs it for every recorded id, and `attachSourceObject` and `setSourceVisible` run it as well.
12. The placement (README D25) is each mesh's own local matrix, `project.worldMatrix(id)⁻¹ ∘ record.nodeMatrix`, with the object's inverse world matrix computed once per apply into the scratch `Matrix4` and each mesh's node matrix multiplied into it, with `matrixAutoUpdate = false` and `matrixWorldNeedsUpdate = true`. The mesh's own world matrix is then exactly the imported node's, whatever the document node has become: before voxelization the object's transform is that matrix, so the local result is the identity, and after `applyVoxelizeResult` made the object translation-only it is the `-origin` offset that keeps the raw mesh where the import put it. Writing it on every apply — including every frame's `sync()` — is what stops a mixer track, a rebuild, or a stale `matrixWorld` from drifting a raw mesh away from its import pose. (`worldMatrix` returns a fresh `Matrix4`, so the copy into the scratch is what keeps a per-id apply allocation-free.)
13. `setSourceVisible(enabled)` stores the global override and immediately re-applies it to every recorded source mesh, and `get sourceVisible()` reads the stored flag back. The application is not left to `sync()`: this is a live control, every object holds a payload after a voxelization so nothing is dirty, and a setter that only recorded the flag would show the old state until an unrelated rebuild happened to publish it. `sync()`'s pass stays as the second, redundant path that keeps a source attached or rebuilt later correct; a repeated call with the same value returns before touching a mesh. Nothing else about the rule changes: off, a raw mesh renders only while its object has no payload, so the first voxelization hides it and the raw-versus-voxel comparison needs the override, and a source mesh whose object is later deleted simply stops being reached, because its entry is gone.
14. `contentCenterOf(id)` is the local-space center of one object's own content: `bounds()` of its uniform container mid-pointed cell-wise — `(min + max + 1) * half` per axis with `half = grid.cellSize / 2`, half a cell of that object's own grid past the mid-point, because cell `i` spans one cell from its min corner and the box's center is the middle of its two outer faces. Anything else answers the origin: an `'empty'` placeholder and a payload with no occupied cell have no content to sit in the middle of, and a raw source mesh never counts, because it is display-only and stays on the pose the import put it on (README D25). The value is derived on every call from the container, never stored, and written into no document value: it is what the edit gizmo pivots at (README D37), while `object.transform` keeps meaning the world position of the object's local `(0, 0, 0)`.

15. `previewTransform(id, matrixWorld)` writes one node's local `position`/`quaternion`/`scale` from a world matrix and touches nothing else: the parent's world matrix is divided out first through `project.worldMatrix(parentId)`, the same conversion the document write performs, and an object with no parent takes the matrix as it is. It is the live half of a gizmo drag (README D37), so the object follows the pointer before anything is committed; `sync()` never rewrites a clean object's transform (D4, D22), so the write stands until the commit rebuilds the node from the document — which by then holds the same matrix. An unknown id is a no-op.

## Invariants
- One `Object3D` per document object: after `sync()` the node set equals `project.objects`, every node is a descendant of `mirror.scene`, and the output camera is a child of the scene root named `camera` (D22), so one `AnimationMixer` rooted at `scene` reaches all of them.
- Exactly two cameras exist at runtime: `mirror.camera`, the output camera, and the app's viewport camera, which the mirror never creates, reads, or moves (README D17). `frameAll(camera)` frames only the camera it is given, so `mirror.camera` is never reframed by a view operation.
- `objectOf(id)` returns the mirrored node of a live object and `undefined` for anything else.
- `contentCenterOf(id)` is a pure function of the object's container: the same grid always answers the same point, half a cell
  of that object's own grid past the mid-point of the box its occupied cells span; it is the
  origin exactly when the object has no `uniform` container or that container holds no cell, and writing a cell, clearing one,
  or attaching a payload is the only thing that can move it. It never reads the node, a mesh, a material, or a source mesh,
  and it writes nothing, so a caller may call it as often as it likes.
- `previewTransform` writes only the node's transform, never the document, a mesh, a buffer, or a lookup, and it is
  overwritten by the next rebuild of that object — which is what makes it safe as per-frame drag feedback. Its
  conversion is exactly the one `editor/ops.ts` performs on commit, so a drag never jumps when it is released.
- `sync()` with no dirty marks rebuilds nothing: node, mesh, and lookup identities are unchanged. It does still re-derive every attached source mesh's local matrix and re-parent/visibility — that write is idempotent, touches no document data, and is what keeps the raw meshes correct without anyone having to mark them.
- `CellLookup.cells.length === CellLookup.colors.length === mesh.count`, and index `i` of the lookup always describes instance `i` of that object, with `color` taken from the container.
- Instances exist only for occupied cells, so occupancy is true for everything a ray can hit.
- A mirrored cube is always exactly one of that object's cells, never a fraction of one and never a spill into a neighbour: the cube's edge is the container's `cellSize` and instance `(x, y, z)` is translated to `(x + 0.5) * cell` on each axis, so the cube spans `[x, x + 1]` cells of that object however fine its subdivision is, and two objects at different levels never share a cube size.
- In mask mode no mesh carries an `instanceColor`, so the mask color is the only color in the frame; silhouettes and the lookup are unchanged because geometry, instance matrices, and lookups do not depend on material or instance-color state.
- Viewport-only decorations (the box preview) live on camera layer 1; the raycaster tests layers 0 and 2 and the export camera tests layer 0 alone (README D24).
- A source mesh is a child of its object's mirrored node and of nothing else, appears exactly once under it, and tests layer 2 and no other layer; its `userData.objectId` is the id it was attached with, so `picking.ts` resolves it to that object.
- Every source mesh of one object is placed by **its own** node matrix: the world matrix of a mesh is the imported node's, so an object holding the whole file (README D28) is drawn as the import authored it, each part where its node put it, rather than all of them on one pose.
- A source mesh's world matrix equals the imported node's baked world matrix it was attached with, within floating-point error, at every point in the object's life: while the object still carries that imported transform (the local placement is then the identity) and after `applyVoxelizeResult` made the object translation-only (the local placement is then the `-origin` offset). That is the whole point of the baked node matrix (README D25) — the raw-versus-voxel comparison stays glued to the import, so a mesh that looks misplaced is a placement bug, never an imported one.
- A source mesh renders exactly when `sourceVisible` is true **or** its object's `representation` is `'empty'`: the moment a voxelization attaches a payload the raw mesh hides unless the override is on, which is what keeps an exported frame free of duplicate geometry and makes the comparison a user choice.
- Every write the mirror makes to a source mesh is `parent`, `matrix`, `matrixAutoUpdate`, `matrixWorldNeedsUpdate`, and `visible`, and all happen only inside `applySources`, which `sync()` runs for every recorded id, and which `attachSourceObject` and `setSourceVisible` run too. The mirror never disposes a source mesh, its geometry, its material, or a descendant of it, and `dispose()` drops only the mirror's own records of them.
- The override lands on the next rendered frame with no `sync()` in between: `setSourceVisible` re-applies it to every recorded mesh the moment it stores the flag, so no caller has to mark anything dirty or wait for a rebuild. This is deliberate, and it is the class of mistake to avoid here — a setter that only records intent is wrong for a live control, because after a voxelization every object holds a payload and nothing is dirty, so nothing would ever publish the change. `sync()` re-applying the rule is a second, redundant path, not the path the toggle depends on.
- `setSourceVisible` with the value already stored returns before touching a mesh, so a repeated call is free.
- `sync()` is idempotent for source meshes: attaching the same mesh again, syncing twice, or rebuilding the object's node leaves exactly one child per attached mesh, with the same placement and the same visibility.
- `frameAll` measures exactly the nodes whose layers intersect `{0, 2}`; a layer-1 node is skipped, and a node's layer-2 children are measured with it.
- The selection outline is decoration and nothing else: it is on layer 3 — so `frameAll` skips it, `Picker`'s raycaster never tests it, and the export camera never draws it, and only the pass `renderSelectionOutline` draws it at all — it is built hidden, and at most one object's is visible, because `setSelected` is the only writer and it hides every other, including that object's depth copy. It is remade with the object it belongs to, so the remembered id is re-applied on every rebuild; without that, any payload edit would drop the outline the user is looking at. A transform-only object has none.
- `dispose()` releases every geometry, material, instance buffer, and lookup the mirror created; it never disposes a voxel container, a document value, or an app-owned source mesh. The outline's hull geometry and material are released with the entry that owns them, because both are the library's own copies.

## Errors
- `markDirty(id)` with an id that is not in `project.objects` throws `TypeError` — a stale mark is a bug, and ignoring it silently would leave the mirror wrong.
- `lookupOf(id)` returns `undefined` for an unknown id, an `empty` object, and an object whose payload has no occupied content; it never returns a lookup whose instances do not exist.
- `attachSourceObject(id, source, nodeWorldMatrix)` is a request, not an assertion: an id the project does not hold yet (or no longer holds) is recorded and simply never reached by `sync()` until that object exists, so no error is raised and nothing is attached for it. A mesh already attached under the same id is kept as the single child it already is, and the recorded node matrix is refreshed. A caller that never attaches anything sees no source meshes at all — the layer is empty, not implied by the object. The matrix is cloned, so the caller may keep mutating the one it passed.
- `sync()`, `lookupOf`, `objectOf`, `attachSourceObject`, and `setSourceVisible` never throw for a structurally legal project.

## Dependencies
- `./faceGrid.js` — `applyFaceBorder`, the per-voxel border installed on the one shading material.
- `@pmndrs/vanilla/core/Outlines` — the inverted hull the selection outline is drawn with; it takes the mesh as its
  parent and shares that mesh's `instanceMatrix`, so the mirror hands it the object's own instances rather than a copy.
- `three` — `Scene`, `Object3D`, `Group`, `InstancedMesh`, `BoxGeometry`, `MeshBasicMaterial`, `MeshLambertMaterial`, `PerspectiveCamera`, `DirectionalLight`, `AmbientLight`, `Color`, `Box3`, `Vector3`, `Matrix4` (the source placement and the attachment contract), `Layers`.
- `../document/project.js` — `Project`, `ObjectId`, `SceneObject` (whose `representation` is the payload test of the source-mesh visibility rule).
- `../voxels/uniform/grid.js` — `HexColor`, plus `CELL_SIZE`, the base cell size a grid subdivides; the rendered cube's edge and the cell-center offset are that grid's own `cellSize`, not the constant.
No outer-ring import: no editor, no UI, no capture. A source mesh arrives as an `Object3D` from the caller; the mirror never builds one.

## Tests
- `tests/scene.test.ts` (node environment, no renderer needed: it builds a real `Project` and `SceneMirror` and calls `sync()`) pins the derived voxel geometry, the one place a cell size can go wrong without any document value changing. One `describe`, two cases: a cube the size of the object's own cell centered half a cell past its index — the same cell `(3, 0, 0)` is a width-`1` cube at `3.5`/`0.5`/`0.5` at subdivision 1 and a width-`0.5` cube at `1.75`/`0.25`/`0.25` at subdivision 2, which is `(x + 0.5) * cell` on every axis — and `contentCenterOf` pivoting on that same lattice, `(1, 1, 1)` for the cells `(0, 0, 0)` and `(1, 1, 1)` at subdivision 1 and `(0.25, 0.25, 0.25)` at subdivision 4. The fixtures place the object at `(10, 0, -3)`, so an instance matrix that folded the node's own placement in would fail; the instance translations are read in a sorted list, so instance order never decides the result. Its contract is `codemap/tests/scene.md`.
- The rest of the mirror has no vitest file: mask mode's flat pass and its restore, the instance-to-cell lookup and picking through it, the layer-2 source meshes, `frameAll`, and material and lighting appearance are verified by running the app (README §10), plus the node-side checks below. `tests/timeline.test.ts` binds a stand-in root shaped like this class, so it pins the mixer, not the mirror.
- The source-mesh layer is also checked node-side, where no renderer is needed (a throwaway `vitest` repro against a real `Project` and `SceneMirror`): a mesh attached before its node exists ends up on layer 2 as the object's only child under `userData.objectId`; attaching it twice leaves one child; a `uniform` payload hides it, `setSourceVisible(true)` shows it again, and a rebuild moves it onto the replacement node; `frameAll` moves a camera that saw nothing on layer 0 onto a layer-2 mesh alone. The placement contract is checked the same way against real imported content (79 rotated, non-uniformly scaled nodes of a Sketchfab GLB): every object `applyVoxelizeResult` fills comes out translation-only, and every attached mesh's world matrix still equals its imported node's, before the payload (local placement ≈ identity) and after it (local placement ≈ the `-origin` offset).

## Open questions
- `markDirty` throwing on an unknown id assumes callers clear marks before deleting; if the playback or delete path turns out to mark removed objects, this becomes a documented no-op instead.
