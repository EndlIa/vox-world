# src/three-runtime/import.ts

Ring: 2 · Layer: three-runtime · Depends on: `../document/project.js`, `../voxels/voxelize/colorSampler.js`, `../voxels/voxelize/voxelize.js`, `three`, `three/addons/loaders/GLTFLoader.js`

## Responsibility
Reads a GLB byte buffer into an `ImportedScene`: one `ImportedNode` per mesh node, each carrying its own world matrix, geometry, and `ColorSource`, plus the scene's own name, the loader root, the displayed world bounds and the bounds of the nodes that are voxelized. Flags the dedicated outline shells a stylized export adds, and keeps them out of the voxelizer's input and out of the sizes derived from an import. Also converts an imported scene into **one** voxelizer source and **one** document object. It reads the base color texture's pixels back out of the image and hands them, with the geometry's UVs and the material's alpha cutoff, to `voxels/voxelize/colorSampler.ts`, which owns the sampling rules; it does not sample a texture itself, does not voxelize, does not build render meshes, and owns no scene state.

## Public interface
```ts
type ImportedNode = { sourceId: string; name: string; geometry: THREE.BufferGeometry;
  matrixWorld: THREE.Matrix4; color: ColorSource; sourceMesh: THREE.Mesh; outline: boolean };
type ImportedScene = { name: string; root: THREE.Object3D; nodes: ImportedNode[]; bounds: THREE.Box3;
  voxelizeBounds: THREE.Box3 };
type ImportResult = { ok: true; scene: ImportedScene } |
  { ok: false; error: 'parse-failed' | 'unsupported' | 'empty'; detail: string };
function importGlb(data: ArrayBuffer): Promise<ImportResult>;
function isDedicatedLineOutlineMesh(mesh: THREE.Mesh): boolean;
function buildColorSource(material: THREE.Material): ColorSource;
function buildVoxelizeSource(scene: ImportedScene): VoxelizeSource | undefined;
function adoptImportedScene(project: Project, scene: ImportedScene):
  { objectId: ObjectId; sourceId: string };
```
`ColorSource` is owned by `voxelize/colorSampler.ts`, `VoxelizeSource`/`VoxelizePart` by `voxelize/voxelize.ts`, `ObjectId`/`Project` by `document/project.ts`; none is re-declared here. `scene.name` is the GLB scene's own name (`gltf.scene.name`), or `'Imported scene'` when the file names no scene, so one import is never nameless. The `ColorSource` this file builds always carries `baseColor` and `alphaTest` (the material's `material.alphaTest`, `0` when it has no cutoff); it carries `texture` only when the material has a base color map whose image could be read back *and* the geometry has UVs, `uv` whenever the geometry has a `uv` attribute, and `vertexColors`/`vertexColorSize` only when the material asks for vertex colors and the geometry has them. `outline` is `isDedicatedLineOutlineMesh(node.sourceMesh)`; `bounds` covers every node, `voxelizeBounds` only the non-outline ones (and is the empty box when every node is an outline). `sourceId` is a per-file key for a node (`node-<gltf node index>`); it names a node in an error, and nothing pairs nodes to objects through it any more.

## Internal logic
1. Container check: magic `0x46546C67`, `version === 2`, a complete chunk table; otherwise `parse-failed` naming the field. Decode the JSON chunk and read `extensionsRequired`.
2. `extensionsRequired` containing `KHR_draco_mesh_compression` or `EXT_meshopt_compression` → `unsupported`, detail listing them. Every other extension is left to `GLTFLoader`, which either loads it or fails into step 3.
3. `new GLTFLoader().parse(data, '', onLoad, onError)` wrapped in a Promise. A rejection, an error callback, or a structurally broken GLB → `parse-failed` with the loader message as `detail`.
4. `root.updateMatrixWorld(true)`, then depth-first traversal of `root`. Each `Mesh` becomes an `ImportedNode` in traversal order: `geometry` (referenced, not copied), `matrixWorld = mesh.matrixWorld.clone()`, `name = mesh.name`, `outline = isDedicatedLineOutlineMesh(mesh)`, and `sourceId = 'node-<index>'` from `parser.associations.get(mesh)?.nodes` — a GLTF node index, unique per file and stable across runs, never a document `ObjectId`. The scene's own name is read once, before the traversal: `gltf.scene.name` when the loader gave it one, `'Imported scene'` otherwise.
5. `isDedicatedLineOutlineMesh` is the name-only rule: at least one assigned material, and *every* material of `mesh.material` (a single material is wrapped in an array) named exactly `line` after `trim().toLowerCase()`. So `Line`, `LINE` and ` Line ` all match, `Line2`/`lines`/an unnamed material do not, a mesh with an empty material array is not an outline, and mixing one `line` material with any other is not either. Colour is never consulted: an ordinary black part of a model (a tire, a window frame) is content the user asked for, so a black-material heuristic would delete real geometry. This is the port of shithill `54b73b6`'s `isDedicatedLineOutlineMesh` (README D27).
6. `color = colorSourceOf(mesh)`, which assembles the node's `ColorSource` from the material and the geometry:
   - **factor, texture and cutoff** from `buildColorSource(material)`: the material's `color` as `Color.getHex()`, or `0xffffff` when it carries no color at all, plus `map` — the base color slot of a `MeshStandardMaterial` and of the `MeshBasicMaterial` that `KHR_materials_unlit` maps to — plus `material.alphaTest` verbatim, which the sampler uses to colour a below-cutoff texel with the texture's visible average instead of dropping its cell.
   - **uv**: the geometry's `uv` attribute copied into a fresh `Float32Array`, 2 floats per vertex, in the geometry's own vertex order.
   - **vertex colors**: when `material.vertexColors === true` and the geometry has a `color` attribute, the RGB triples are copied into a fresh `Float32Array` with `vertexColorSize = 3` (alpha dropped).
   A texture is attached only when the geometry has UVs, because without them it could never be sampled; the factor and the cutoff stay either way, they belong to the material. Every missing attribute is simply left out rather than filled with a default, and `colorSampler.ts` skips it.
7. Texture pixels are read back once per texture object: a decoded 8-bit buffer (`{ width, height, data }`, the form a KTX-free loader can produce) is used as it stands — a view over it, never a copy — while an image element or bitmap is drawn into an offscreen `document.createElement('canvas')` sized to the image and read back with `getImageData`. The result is cached in a module-level `WeakMap<THREE.Texture, TexturePixels>` keyed by the texture object, so a GLB whose nodes share twelve textures pays for twelve readbacks instead of one per node; only successful reads are cached, so a texture whose image is not readable yet is retried rather than poisoned, and a released file releases its pixels. That one shared `TexturePixels` record per texture is also what lets `colorSampler.ts` key its visible-average cache per texture. `flipY` is not applied: `ImageData` and glTF UVs share the top-left origin, and this is the GLB path. This is the file's only DOM use.
8. Bounds are computed after the traversal, from the finished `nodes` list: `bounds = new THREE.Box3().setFromObject(root)` covers every node, because the raw-mesh display shows all of them and framing has to fit all of them, while `voxelizeBounds` is built with `expandByObject(node.sourceMesh)` over the non-outline nodes only — the inverted hulls are drawn around the model, so letting them in would inflate the octree root and the default voxel size for content they do not cover (README D27). A file that is nothing but outlines leaves `voxelizeBounds` empty, which is a state the consumer handles. Zero mesh nodes → `empty`, with the node count in `detail`. Skinned meshes are read in their bind pose; skinning, morph targets, and in-GLB animation are ignored, not failures.
9. `buildVoxelizeSource` returns one `VoxelizeSource` for the whole scene — one import is one source, and therefore one payload — or `undefined` when it has nothing to voxelize (every node is an outline, which the loader can produce as easily as `nodes.length === 0`, which `importGlb` already rejects). Its `parts` are the **non-outline** nodes in `nodes` order, each with `positions` a fresh `Float32Array` with every vertex multiplied by `node.matrixWorld`, so the soup is world space and downstream voxelization needs no hierarchy, and `index` the geometry's index or a generated `0..n-1` `Uint32Array` for non-indexed geometry. Each part carries the node's own `ColorSource` unchanged — per-material base color factor, vertex colors, texture, UVs and `alphaTest`, all indexed by the same soup vertices, in the geometry's own vertex order — and the source's `sourceId` is `'scene-<scene.name>'`, keyed by the name `adoptImportedScene` names the object with. Skipping outlines here is what keeps their spurious shell out of the palette and the cell set; they are not skipped anywhere else.
10. `adoptImportedScene` creates exactly **one** document object with `project.createObject({ name: scene.name, representation: 'empty' })` and returns `{ objectId, sourceId: 'scene-<scene.name>' }` — the identity transform `createObject` gives it, and a null parent: the model's placement is not the object's transform but each node's baked `matrixWorld`, which every source mesh carries and which voxelization bakes into the one source, so an identity object transform is correct before and after the payload attach. The returned `sourceId` is the id `buildVoxelizeSource` builds for the same scene — the key `editor/ops.ts`'s `applyVoxelizeResult(project, result, { attachTo })` maps onto `objectId`, so voxelization attaches the payload to this object instead of creating a duplicate one, the object keeps the name the import gave it, and the raw-mesh toggle still has its `sourceMesh` for every node. An outline node never appears in the source, so its geometry never reaches a payload; it is still a node, so the app attaches its mesh as one of the object's source meshes and the model shows as authored (README D27).

## Invariants
- `ok: true` implies `nodes.length > 0`; a failed import returns no scene and leaves no document object behind.
- `nodes` order is traversal order, and `buildVoxelizeSource` preserves it, so the parts of the one source, and with them the cells of the one payload, are reproducible for the same file.
- Every consumer sees world-space transforms; no consumer needs the GLB hierarchy.
- Imported objects take their identity from `Project` (`obj-<n>`), never from a GLB node index, node name, or uuid (README D3) — while the object's *name* is the GLB scene's, because that name is what the import is.
- `sourceMesh` is retained because it is the comparison source for the raw-mesh toggle; the voxel result never replaces it.
- One import is one object and one source: `adoptImportedScene` creates exactly one object for any scene, `buildVoxelizeSource` returns at most one source, and the source's id is `'scene-<scene.name>'` for the same `scene.name` the object is named after — so the `attachTo` map a caller builds from either one resolves every `VoxelizeOutput.sourceId` of that import, and no code path derives a source from a single mesh node any more.
- `nodes.length` is the object's source-mesh count, while `buildVoxelizeSource(scene)?.parts.length` is that count minus the outline nodes: the object shows the model as it was authored, and the voxelizer only ever sees the model's own surface.
- `buildVoxelizeSource` returns `undefined` exactly when every node is an outline; `importGlb` never returns a scene with no nodes, so the two cases a caller sees are an outline-only file and a file with something to voxelize.
- `outline` is a property of the mesh's material *names* at import time, so `isDedicatedLineOutlineMesh(node.sourceMesh)` agrees with `node.outline` for every node, and no consumer re-derives it from `ColorSource` data (a hex cannot express it).
- `voxelizeBounds ⊆ bounds`: it is built from a subset of the same nodes' world boxes. It may be the empty box (a file of nothing but outlines) — consumers fall back to `bounds` then.
- `unsupported` and `empty` are decided before any document mutation, so a rejected file cannot leave a half-adopted scene.
- A `ColorSource` holds plain data only: hexes, numbers, typed arrays, and an anonymous `{ width, height, pixels }` record. No `THREE.Texture`, image, or canvas is stored in it (README D1), so a source stays structured-cloneable.
- The readback is cached per texture *object*, so nodes sharing a texture share one `{ width, height, pixels }` instance and one texture never yields two different readbacks — which is also what makes the sampler's per-texture visible average meaningful (one record, one average).
- A texture is attached only together with `uv`, so a source never carries pixels that cannot be sampled; `uv` and `vertexColors` are copied in the geometry's own vertex order, which is the order `buildVoxelizeSource` preserves within each part.
- `alphaTest` is read from the material and travels whether or not the source ends up with a texture: it is the material's cutoff, and a node whose map could not be read back still describes its material correctly.
- The `ColorSource` of a part is the very object the node holds, so a node's material description and its voxel colours cannot drift, and the texture readback and the sampler's visible-average cache are paid once per texture for the whole import, not once per part.

## Errors
- `{ ok: false, error: 'parse-failed', detail }` — bad GLB header, version, or chunk table, malformed JSON chunk, or a `GLTFLoader` failure. `detail` carries the loader or validator message.
- `{ ok: false, error: 'unsupported', detail }` — a required compression extension, or a mesh node whose geometry has no usable `position` attribute. `detail` names the extension or the node index.
- `{ ok: false, error: 'empty', detail }` — no mesh node with geometry in the file.
- `adoptImportedScene` throws `TypeError` when `project` is not a `Project`; the other functions never throw for scene content, because `importGlb` rejected the unusable cases.
- A texture is never an error: no image, no `document`, a size-less, short, or non-8-bit buffer, an image that cannot be drawn, a readback the browser refuses (a cross-origin canvas is tainted), and a geometry without UVs all drop the texture (or the UVs) and leave the node with its factor and vertex colors. A texture cannot make an import fail, and an unreadable one cannot make a node white.

## Dependencies
- `three` — `BufferGeometry`, `Matrix4`, `Box3`, `Mesh`, `Object3D`, `Color`, `Texture`.
- `three/addons/loaders/GLTFLoader.js` — the GLB parser (README §3 addon export map).
- `../voxels/voxelize/colorSampler.js` — `ColorSource` only.
- `../voxels/voxelize/voxelize.js` — `VoxelizeSource`, `VoxelizePart` only.
- `../document/project.js` — `Project`, `ObjectId`.
- The DOM, for the texture readback only: `document.createElement('canvas')`, `getContext('2d')`, `drawImage`, `getImageData`. It is the sole DOM dependency, it is guarded by `typeof document === 'undefined'`, and it is reached only for an image that is neither absent nor a decoded 8-bit buffer.
No outer-ring import: no editor, no UI, no renderer, no scene mirror.

## Tests
No test file imports this module: `GLTFLoader` needs a DOM and the texture readback needs a canvas, and the node environment deliberately has neither. The rules it feeds are pinned next door by `tests/voxelize.test.ts`, which builds `ColorSource` values by hand — including the alpha-masked path — (product precedence, UV centroid, repeat addressing, the visible average, fallbacks, `RangeError`s). The import path itself is verified by running the application against `public/forest.glb`, the reference case: 79 nodes, 22 of them `*_Line _0` shells whose every assigned material is named `Line` (the predicate holds for all 22 and for no other node), 57 nodes textured, every node carrying `uv`, and `alphaTest` non-zero on 16 nodes (glTF `MASK` cutoffs of 0.00457 / 0.06552 / 0.07771, which is what puts the masked path to work). Its glTF scene is named `Sketchfab_Scene`, which is the name both the import and its one object take.
- Outline exclusion, measured on that file rather than argued: the 79 nodes total 17628 triangles, the 22 shells own 6410 of them, and `buildVoxelizeSource` returns one source whose 57 parts hold the remaining 11218 — the count the app reports as `voxelized 28893 cell(s) from 11218 triangle(s)` for that one payload. The 28893 cells are that file's measurement of the one-object model: the same 57 meshes voxelized as 57 separate payloads used to report 32854 cells, and the 3961 cells the difference accounts for are the ones two or more meshes claimed — the stones inside the soil box, the barbecue and the fire inside each other — which can no longer coincide. The object list holds the two rows the run has: `Sketchfab_Scene · uniform · 0.147 m` (the GLB scene's own name, `14.1552 / 96` of its outline-free extent) and the boot demo cube, and switching `Representation` to `octree` re-voxelizes the retained import into `voxelized 12161 cell(s) from 11218 triangle(s)` with the row becoming `Sketchfab_Scene · octree`.
- The sampled masked colour is checked against the texture itself on a foliage node (`Circle_foliage_base_color_0`): a triangle whose centroid texel is transparent resolves to the visible average (`#e0e95b`, the byte average `(224, 233, 91)` of the 341311 texels the cutoff keeps), while the same sample without the cutoff falls back to the `#ffffff` factor — the average, not the hole's own colour.
- On that file `voxelizeBounds` happens to equal `bounds` exactly: its shells are inside the extremes the model's own meshes already reach, so the exclusion changes no size there. The rule still holds for a shell that does stick out, and the app's defaults are read from `voxelizeBounds` (see `app/main.md`).
- `adoptImportedScene` is exercised against a real `Project` in the same run: exactly one object, named `Sketchfab_Scene` after the GLB scene, at the identity transform `createObject` gives it, with a null parent and an `obj-<n>` id; the per-node `bySourceId` map is gone, replaced by the single `{ objectId, sourceId }` pair; and all 79 nodes' meshes are attached to that one object — the 22 outline shells among them, so the model is displayed as authored while only the 57 meshes with geometry reach the payload.
